# Escalate vs Clarify vs Solve

> Match the response to the *reason*, not the customer's mood.

| Situation | Response |
|---|---|
| Customer explicitly asks for a human | **Escalate** (stop trying to resolve) |
| Policy is silent / ambiguous on the case | **Escalate** (don't invent a policy) |
| Workflow stuck, no progress | **Escalate** |
| Multiple records match (e.g. several customers) | **Clarify** — ask for identifiers, don't guess |
| Requirements ambiguous | **Clarify** before acting |
| Frustrated but the issue is solvable | **Acknowledge + solve** |
| Negative sentiment, solvable | **Solve** (sentiment ≠ escalation trigger) |

## Bottom line
Escalation is driven by **policy/workflow** triggers, not by
**sentiment** or **self-reported confidence**. When information is
ambiguous (multiple matches, unclear requirements), **clarify** first
rather than guessing. Escalations carry a **structured handoff
summary**, never a vague one. See [[escalation-patterns]].
